## Mission Briefing

### Why This Matters
Before a **large restructure** of GitHub repositories, we must perform hygiene passes.
Small issues compound at scale — one trailing space multiplies into hundreds of noisy diffs.
One overlong title breaks PR templates. One symbol breaks shell scripts.

Clean first. Restructure second. That is the one-hertz way.

### Scope — Issues to Address
```
HYGIENE_MANIFEST v1.0
----------------------
CLASS A — Whitespace
  [ ] Trailing spaces (end of line)
  [ ] Trailing newlines (end of file — ensure single \n)
  [ ] Mixed tabs/spaces (indentation consistency)
  [ ] Windows CRLF line endings (\r\n → \n)

CLASS B — Symbols & Special Characters
  [ ] Filenames with spaces → replace with underscore or hyphen
  [ ] Filenames with special chars: &, #, %, ?, !, @, (, )
  [ ] Unicode in filenames that break shell/git ops
  [ ] Economic symbols in wrong context (€, ₿, §, ∞ — flag, not remove)
  [ ] Consciousness symbols in filenames (flag for review, not auto-remove)

CLASS C — Titles & Commit Messages
  [ ] File titles > 255 chars (filesystem limit)
  [ ] Commit subject lines > 72 chars (git convention)
  [ ] Markdown H1 titles > 80 chars (readability)
  [ ] Titles with leading/trailing spaces
  [ ] Titles with double spaces
  [ ] Titles ending in punctuation (trailing period, comma)

CLASS D — Git-Specific
  [ ] .gitignore coverage (sensitive files, __pycache__, *.pyc)
  [ ] Large files > 50MB (should use LFS or exclude)
  [ ] Empty directories (git doesn't track them — need .gitkeep)
  [ ] Files with no extension in wrong locations
  [ ] Branch names with spaces or special chars

CLASS E — Structural
  [ ] README.md presence in each repo root
  [ ] LICENSE presence check
  [ ] Deeply nested paths (> 8 levels — Windows compat issue)
  [ ] Duplicate filenames differing only by case (case-sensitivity issues)
```
